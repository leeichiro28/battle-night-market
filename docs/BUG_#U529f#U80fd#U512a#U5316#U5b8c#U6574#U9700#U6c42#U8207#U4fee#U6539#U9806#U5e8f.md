### P0-1｜PVP 血量變 0 但對戰沒有結束 → ✅ 已更新

- 但 PVP 對戰仍然沒有結束。
- 需要確認死亡判定、勝負判定以及對戰結束流程。

> **實際原因(第一輪判斷，不完整)**：一開始以為是「結束得太快、畫面來不及顯示」，所以加了「結果畫面留著顯示3.5秒」+「自動重試修復卡住的對戰」。這兩個修改本身沒有錯、也還是需要，但沒抓到真正的根本原因。
> **⚠️ 真正的根本原因(你實測回報後才挖到)**：資料庫的 `career_pvp_queue` 表格缺了 `win_streak` 這個欄位——這個表格是很早期就建立的，但 `win_streak`(連勝數)是後來企劃加碼「連勝加成」時才補進表格定義裡，可是 `supabase-schema.sql` 只有 `create table if not exists`，對「已經存在的表格」完全不會補欄位，所以正式環境的表格從頭到尾都沒有這個欄位。而負責「PVP結算、判定勝負」的 `finish_career_match` 從最早的版本就已經在用這個欄位，結果就是每一次要結算對戰都會直接報錯、整個結算失敗，對戰就永遠卡在「進行中」——不管是血量打到0，還是這次新加的投降，都會失敗。之前錯誤是被靜靜吞掉(只有寫到瀏覽器console.log，畫面上完全看不出來)，這次是因為你測試投降功能，投降有跳出錯誤視窗，才第一次真正看到這個錯誤訊息。
> **修改方式**：在 `supabase-schema.sql` 補上 `alter table career_pvp_queue add column if not exists win_streak/final_rank/reward`，不管表格是什麼時候建立的都會補齊這三個欄位。
> **修改檔案**：`assets/career.js`(第一輪修改)、`supabase-schema.sql`(這次補的根本修復)
> **⚠️ 這次修改務必要到 Supabase SQL Editor 重新執行 `supabase-schema.sql` 才會生效，不然投降、正常打到血量歸零都還是會結算失敗。**
> **待測試**：SQL跑完後，實際打一場PVP到血量歸零，確認正常出現獲勝/戰敗畫面；也測試一次投降，確認不會再跳出「column ... does not exist」的錯誤。

## P1-1｜合成列表自動收合 → ✅ 已更新
合成列表會自己自動收合。

可以改成三排裝備種類：
```text

防具
吊飾
```
不要讓列表自己跳回收合狀態。

> **實際原因**：程式裡其實已經有一段防呆(玩家正在跟下拉選單互動時，跳過每秒一次的重繪)，但那段防呆只套用在「每秒重繪」這顆計時器，沒有套用在「Realtime資料庫通知觸發的重繪」——而只要事件裡任何一位玩家的爬塔資料有變動(例如有人在特訓、有人裝備變化)，就會觸發這個Realtime重繪，把所有人畫面上開著的下拉選單一起強制收合。這就是「之前修好、後來又出現」的原因：第一次修的是每秒重繪那條路徑，Realtime這條路徑一直沒補到。
> **第一次修法(已證實不夠)**：當時只加了「玩家正在操作下拉選單就先不重繪、晚一點再重試」。問題是這只是延後，治標不治本：`career_progress` 這張表整場活動所有人共用，任何一位玩家狂點練功/特訓/買裝備，**每一位玩家**的畫面都會收到事件、跟著重繪，人一多就等於一直在重繪，永遠找不到「晚一點」的空檔。而且選單選完的值沒有保存，重繪後會被重設回第一項；玩家按下「合成」按鈕的瞬間(按下到放開之間)如果剛好重繪，按鈕被換掉、點擊會落空，甚至讀到被重設的選項而合成錯東西。
>
> **根本修法(2026-10)**：不是讓玩家等，而是讓「別人的操作」根本不會重繪我的畫面：
> 1. **只聽自己那一列**：Realtime 通知帶有 `player_id`，不是自己的資料變動就直接略過(別人的進度只影響排行榜，排行榜本來就由8秒一次的背景掃描更新)。
> 2. **內容沒變就不重繪**：每次重繪前先比對HTML，跟上一次一模一樣就不動DOM(合成分頁沒有倒數文字，每秒計時器大多屬於這種)。
> 3. **選單的值記在變數裡**：`synthesisChoice`，重繪後照樣選在原本那一項，按合成時也是讀這個變數，不會合成錯東西。
> 4. **真的必須重繪時才暫緩，而且是事件驅動**：玩家正按著按鈕、或選單/輸入框有焦點時，先標記「待重繪」，等放開(pointerup)、選完(focusout)再補做一次，不再用輪詢反覆重試。
> **修改檔案**：`assets/tower.js`
> **待測試**：①兩個帳號進同一場活動，A 停在合成分頁打開下拉選單，B 狂點練功已通關樓層，A 的選單不應該收合、也不應該跳回第一項。②A 選好後按「合成」，應該合成選的那一種。③B 的練功/特訓倒數、結果不受影響。**這次只做過語法檢查，沒有實機多人測過**，請照上面兩人情境驗一次。

## 29-3｜數值遞減(定案規則) → ✅ 已更新(階段一，見第三十章)

- **角色升級的自由數值點**：Lv.100 以前每升一級 +2 點(不變)；**超過 Lv.100 之後，每 3 級才給一次 +2 點**(升到 Lv.103、106、109… 才給)。
